## 🎯 一、核心定位

**GOAA.AI 不是傳統的 AI 聊天工具**。

GOAA.AI 的核心定位是:

> **AI 勞動力平台 (AI Labor Platform)** + **AI Runtime Operating System (AI 運行時操作系統)**

讓 AI 真正幫助用戶完成現實世界中的任務:
- 文件處理 / 表格填寫 / 自動化任務
- 瀏覽器操作 / 本地 AI 執行
- 多智能體協作 / 專業服務連接
- 技能市場 / AI Worker 網絡

### 最終願景
構建一個由 **Client + Provider + Worker Network + Runtime OS + Skill Marketplace** 組成的 **AI 生產力經濟系統**。

## 👥 三、三層角色體系 (命名規範強制)

GOAA.AI 的商業結構由三個核心角色組成:

| 層級 | 角色 | 核心定位 |
|---|---|---|
| **第一層** | **Client (用戶)** | 需求發起者 |
| **第二層** | **Provider (專業服務者)** | 真人專業服務提供者 |
| **第三層** | **Worker Network (AI Worker 網絡)** | AI 生產與執行網絡 |

### 命名規範強制 (Database / Code / Doc 統一)

| 概念 | 統一命名 | 禁止 |
|---|---|---|
| 用戶 / 客戶 | **Client** | user, customer (混用) |
| 真人服務者 | **Provider** | **Agent (這個詞保留給 AI Agent)** |
| AI 數字勞動力節點 | **Worker** | node, slave (含義不對) |
| AI Agent | **Agent (= AI Agent)** | 不可指真人 |
| 可售賣能力 | **Skill** | feature, plugin (太弱) |
| Worker 生產的成果資產 | **Achievement** | output, result (太弱) |

### 資料庫建議命名
- `clients`
- `providers`
- `v4_agents` 或 `ai_agents`
- `workers`
- `skills`
- `skill_marketplace`
- `skill_subscriptions`
- `worker_events`
- `dispatch_plans`
- `tasks`

**禁止把真人服務者繼續放進 agents 語義空間。**

## 🤝 五、Provider 商業層

### 5.1 為什麼不用 Agent 這個詞

傳統行業: 房產經紀 / 保險經紀 / 稅務顧問 / 律師通常被稱為 Agent。

但在 AI Runtime 世界中: **Agent 已經被 AI Agent 佔用**。

為了避免系統與資料庫混亂, GOAA.AI **強制統一改名為 Provider (服務提供者)**。

### 5.2 Provider 對象

Provider 是**真人專業服務者**:
- 房地產經紀 / 保險經紀 / 稅務顧問
- 會計師 / 移民顧問 / 律師
- 金融顧問 / 醫療顧問 / 教育顧問

核心需求:
- 獲取客戶 / 降低工作量 / 提高成交率
- 自動化表格處理 / AI 輔助工作流

### 5.3 Free ($0)

Provider 可免費測試 AI / 上傳文檔 / 體驗 AI 自動分析 / 填表 / CRM。

### 5.4 Pro ($39.99 / 月)

當 Provider 希望「**獲取客戶訂單**」時, 進入 Provider Pro:
- AI 自動接單 / Client Leads
- AI 自動整理客戶資料 / 表格 / 總結 / 報價 / 跟進
- AI CRM / 提醒 / 工作流管理

### 5.5 AiKa Box ($999 硬件 或 $99 / 月)

Provider 可購買 **AiKa Box** 作為「**本地 AI Runtime Worker**」, 部署在辦公室。

### 7.3 Worker Credit Economy (積分經濟)

每個 Worker 根據以下貢獻獲得 Credits:
- CPU 使用 / GPU 使用 / Token 消耗
- Runtime 時間 / 執行任務 / 技能生產
- Skill 維護 / Skill 收益分潤

#### Worker 收益模型範例

| 行為 | 收益 |
|---|---|
| 文檔 OCR | Credits |
| 瀏覽器自動化 | Credits |
| Docker 執行 | Credits |
| AI 視頻處理 | Credits |
| 技能生成 | Credits |
| 本地 GPU 推理 | Credits |

#### 結算規則
- Worker 成本與收益必須**可審計**
- 核心字段: `task_id` / `worker_id` / `runtime_cost` / `api_cost` / `revenue` / `profit` / `credits` / `duration` / `skill_id` / `dispatch_plan_id`
- QS < 0.6 → 無 payout, task 返回 redo
- Security = 0 → 強制歸零 + 安全警報
- 只有本地 AiKa boxes 賺 Credits, 雲端 VPS boxes 不
- 暫無提現, Credits 抵月費 ($39.9 = 3,990 Credits)

## 🛍️ 八、Skill Marketplace (技能市場)

**這是 GOAA.AI 長期最重要的商業層**。

未來真正值錢的**不是聊天**, 而是「**可執行技能**」。

### 8.1 Skill 定義

Worker Network 生產的標準化能力:
- AI Skill / 自動化工作流
- Browser Automation 流程 / OCR + 文檔分析流程
- 自動填表工具 / AI 視頻生成工具
- AI 信件管理工具
- 行業專用 Prompt + Runtime Workflow
- Provider 專用業務工具 / Client 生活服務工具
- 本地 AiKa Box 可執行插件
- 雲端 Runtime 可調度能力
- 數據處理模板 / 報告生成模板
- 多步驟 Agent Workflow

### 8.2 Skill 商業模式

#### Consumer Skill (Client 端)
- 例: 「家庭信件管理」
- 收費: **$2.99 / 月**
- 收益分成: 50% 平台 + 50% Worker 生產者

#### Professional Skill (Provider 端)
- 例: 「AI 視頻自動生成」
- 收費: **$9.99 / 月**
- 收益分成: 50% GOAA 平台 + 50% Worker / Skill 開發者

### 8.3 收益計算

```text
總收入 = 月費價格 × 有效訂閱人數
平台收入 = 總收入 × 平台分成比例
Worker收入 = 總收入 × Worker分成比例
淨利潤 = 總收入 - Runtime成本 - API成本 - 結算成本
```

#### 範例: 家庭信件管理 Skill
- 月費: $2.99
- 訂閱: 1,000 人
- 本月總收入: $2,990
- GOAA 平台收入: $1,495
- Worker 分潤: $1,495
- Runtime 成本: $210
- 估算淨利潤: **$2,780**

#### 範例: Provider 視頻生成 Skill
- 月費: $9.99
- 訂閱: 300 個 Provider
- 本月總收入: $2,997
- GOAA 平台收入: $1,498.50
- Worker 分潤: $1,498.50
- Runtime 成本: $520
- 估算淨利潤: **$2,477**

### 9.3 成果完整生命週期

**8 個階段**:

1. **需求來源** — Client 高頻需求 / Provider 痛點 / 用戶反饋 / 市場機會 / Worker 自主發現
2. **生成開發任務** — skill_design_task / workflow_build_task / prompt_engineering_task / runtime_test_task / ui_config_task / billing_config_task
3. **Worker 開發 Skill** — Skill 邏輯 / Prompt 模板 / Runtime Workflow / 輸入輸出 / UI / 計費 / 安全 / 錯誤處理 / 日誌
4. **測試與驗收** — 功能 / 安全 / 成本 / 多輪輸入 / Client 場景 / Provider 場景 / Runtime 成本 / 失敗回滾
5. **封裝與版本化** — Skill Package + Version + Runtime Config + Billing Config + UI Display + Permission Config
6. **上傳到技能市場** — Client / Provider / AiKa Box 三端分發
7. **訂閱與計費** — 立即開通權限 + 月費計費 + Runtime 可調用 + Worker 收益累計
8. **反饋與升級** — 評分 / 反饋 / Bug / 新需求 → patch_task / upgrade_task / optimization_task → 回到 Worker Network

形成完整閉環。

### 9.4 用戶反饋自動生成 Worker Task (6 種映射)

| 反饋類型 | 自動生成任務 | 下游響應 |
|---|---|---|
| Bug / 崩潰 / 閃退 | `patch_task` | 回滾穩定版 + 生成補丁任務 |
| 體驗不好 | `ux_improvement_task` | 派發 UI / UX Worker 優化 |
| 速度慢 | `optimization_task` | 優化 Runtime 流程與執行步驟 |
| 想增加功能 | `feature_task` | 進入下一版本迭代 |
| 輸出錯誤 / 幻覺 | `prompt_fix_task` | 修正 Prompt 與 Few-shot 樣例 |
| 成本太高 | `cost_optimization_task` | 優化模型路由與 Worker 調度 |

### 9.5 Skill 一鍵啟停機制

用戶向右滑動藍色按鈕後系統自動:
- 創建 subscription_id
- 開啟 Skill / 開始計費
- 分配 Runtime 權限
- 寫入 billing ledger + usage ledger
- 激活 Worker 工作流

用戶關閉按鈕後系統自動:
- 停止下月計費 + Runtime 調用
- 保留歷史記錄
- 更新訂閱狀態 + 成果市場收益統計

訂閱狀態: `active` / `paused` / `cancelled` / `expired` / `trial`

### 9.6 版本管理 (Semver)

每個 Skill 必須版本化:
- 主版本 (v1.0.0 → v2.0.0): 重大功能變化
- 次版本 (v1.0.0 → v1.1.0): 新增功能
- 補丁版本 (v1.0.0 → v1.0.1): Bug 修復

每個版本必須記錄:
- 發布日期 / 開發 Worker / 變更說明
- Runtime 成本變化 / 收益變化 / 用戶評分變化
- 回滾記錄 / 兼容性

#### Rollback 機制
新版本出錯 → **一鍵回滾到上一個穩定版本**, 商業 Skill 必須.

## ⚖️ 十二、產品設計不走偏 5 原則 (規範 #35 升級)

> **這 5 條原則是 GOAA.AI 的法律**, 違反必須重新審視設計。

### 原則 1: 先定義角色, 再設計功能

任何功能必須先明確服務對象:
- Client / Provider / Worker / AI Agent / Skill

**禁止混用 Agent / Worker / Provider 的概念。**

### 原則 2: 先確定業務閉環, 再開發頁面

任何頁面必須服務於閉環:
- 獲取需求 → 提供服務 → 執行任務 → 生產 Skill → 收費分潤 → 收集反饋 → 繼續升級

**禁止為了頁面而頁面。**

### 原則 3: Worker V5.0 優先於前端商業擴張

在 Worker V5.0 沒有穩定形成生產線之前:
- 不盲目擴展 Client 功能
- 不盲目擴展 Provider 功能
- 不急於上線複雜 Skill Marketplace
- 不急於做大規模營銷

**必須先保證 Worker 能穩定生產成果。**

### 原則 4: Runtime Truth 優先於視覺設計

GOAA.AI 的核心不是好看的 UI, 而是:
- 真實任務 / 真實執行 / 真實收益
- 真實成本 / 真實日誌 / 真實回放 / 真實成果

**UI 只能服務 Runtime Truth, 不能掩蓋虛假數據。**

### 原則 5: 技能必須資產化

Worker 開發的 Skill **不能只是一次性任務**, 必須:
- 封裝 → 版本化 → 測試 → 上架 → 計費 → 反饋 → 升級 → 回滾

**最終成為 GOAA.AI 的長期數字資產。**

## 十二、Three-Tier Product Boundary Doctrine（三端產品邊界鐵律）

> **章節等級**：核心商業模式正式章節
> **立規日期**：2026-05-19
> **規範同步**：`docs/AGENTS.md` Three-Tier Product Boundary Doctrine 為完整版

### 12.1 最高鐵律

> Worker 負責生產能力；Provider 負責接單、跟單、調用專業 Skill 並交付服務；Client 負責提出需求、查看進度、與 Provider 互動並使用生活化 Skill。

此句為 GOAA.AI 商業模式三端邊界的最終定義，所有商業決策、收費結構、UI 設計、市場文案必須對齊此句。

---

### 12.2 三端商業邊界

#### Worker（內部生產線）

**當前階段定位**：GOAA 內部生產線，不面向普通用戶開放，不產生對外收費。

**功能範圍**：
- 內部任務調度
- Worker V5.0 開發
- Runtime 測試
- 技能（Skill）開發
- 工具鏈驗證
- Skill Marketplace 早期生產

**未來商業化路徑**：成熟後（律師意見書 + KYC + ToS + Runtime 沙箱完備）開放給外部開發者，採用 Credits + 50/50 分潤模式。

**當前商業層**：**無對外收費**。

---

#### Provider（專業服務工作台）

**核心定位**：專業服務者的接單、跟單、Skill 調用、審核交付工作台。**不是開發者平台。**

**前 6 個月唯一商業主線**。

**商業層**：
| 層級 | 價格 | 功能 |
|:---|:---:|:---|
| Provider Free | $0 | 基礎接單 |
| **Provider Pro** | **$39.99/月** | 完整 AI 工作台 + Provider Skill 調用 |
| Setup Fee | $199 一次性 | Onboarding + 帳號配置 |
| AiKa Box Pro Alpha | **$1299** | 本地 Worker Runtime 硬體（含 RTX 3060 12GB + Ryzen 5 5600 + 32GB + 1TB）|

**Provider 邊界**：
- 不開發 Skill
- 只訂閱與調用付費 Provider Skill
- 最終人類審核後交付
- 不暴露 Worker 調度 / Credits 細節 / Runtime 日誌

---

#### Client（需求方平台）

**核心定位**：需求方入口。Client 與 Provider 是買賣雙方的交換場景。

**Phase 5+ 啟動**（前置條件：50+ 活躍 Provider + 5+ 生活化 Skill + Provider 接單能力驗證）。

**商業層**：
| 層級 | 價格 | 功能 |
|:---|:---:|:---|
| Client Free | $0 | 基礎需求發布 + 查看進度 |
| **Client Plus** | **$19.99/月** | 完整生活化 Skill 池 + 優先匹配 |

**Client 邊界**：
- 不看 Worker 調度
- 不看 Credits 成本細節
- 不看 Skill 開發流程
- 不看 Runtime 日誌
- 僅使用生活化 Skill（非專業判斷）

---

### 12.3 Skill Marketplace 分層

Skill Marketplace 必須**按使用者三層分流**，不可混合展示。

| 層 | 對象 | 範例 | 上架狀態 |
|:---|:---|:---|:---:|
| **Client Skill** | 普通用戶 | 家庭信件管理、IRS 信件提醒、帳單整理、房貸壓力測試、家庭文件分類 | Phase 5+ |
| **Provider Skill** | 專業服務者 | Insurance Needs Analysis、IUL/Term 草稿、客戶 intake、follow-up、IRS Letter Triage | Phase 3-4 |
| **Worker / Developer Skill** | 開發者（後期）| Skill 開發、Runtime 插件、Browser automation、OCR pipeline、行業 workflow | 律師意見書後開放 |

**當前階段嚴禁**：Worker / Developer Skill 暴露給 Client 或普通 Provider。
