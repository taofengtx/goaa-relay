## 1. 決定性結論:`qwenpaw.log` ≠ 對話記錄

`C:\Users\Administrator\.qwenpaw\qwenpaw.log`(5.59 MB / 39,011 行)是**應用程式日誌**,不是對話本體。

實測證據:
- 行型分布:INFO 15,645 / WARNING 11,200 / ERROR 84(格式 `時間 | 等級 | 檔案:行號 | 訊息`)
- 對話結構 `"role":"user|assistant"` 命中 **0 筆**

→ **不可作為 RAG corpus 來源。** 嵌入它 = 嵌入啟動日誌噪音。

## 2. 對話真實落點(RAG corpus 來源)

日誌啟動行揭露:QwenPaw 記憶由 **ReMe**(`ReMeLightMemoryManager`)管理。對話沉澱在:
- `workspaces/default/sessions/*.json` → `agent.memory.content[]`(記憶陣列,**已驗為 populated**)
- `workspaces/default/chats.json`(session 元數據索引:id / name / session_id / channel / status / 時間戳)
- `agent.memory._compressed_summary`(壓縮摘要 — **二手,僅備援,不優先嵌入**)

最大 session:`claude_test_001_efc4316d-...json`(839 KB)→ 歷史對話量級夠大,值得做 RAG。

## 3. ★安全發現(P0,排在 RAG 前)

`qwenpaw.log` 內含**明文 secret**(掃描計數,值未記錄):
- `sk-` 金鑰 ×5
- `ghp_` GitHub token ×1
- password 樣式 ×2

此即 Zoho 反覆 revoke 的根因實證:secret 經由日誌持續落盤。

**白天 P0 動作**:
1. 上述 8 個憑證**全部視為已洩漏,逐一 rotate**(GitHub token 優先 — 具 repo 寫入權)
2. `qwenpaw.log`(及 `*.log`)加入 `.gitignore`,**絕不 commit**
3. 確認 `.qwenpaw\` 不在 OneDrive / 任何同步、備份路徑
4. 既有 Zoho 第 3 次 revoke + Anthropic API key 確認 — 併入同一份 rotate 清單

## 4. RAG POC 就緒度(架構已定,一格待驗)

預設架構(規範 #30 不過度架構,(A) 可逆):
- **Stage 0(AiKa-1)**:extractor 讀 `sessions/*.json` → 取 `memory.content[]` → 正規化 `corpus.jsonl`(`session_id / ts / role / text`)。**第一步是 redaction**(遮 `sk-` / `AIza` / `ghp_` / password / master_key),確認乾淨才往下。
- **Stage 1(AiKa-2)**:`corpus.jsonl` → Ollama `nomic-embed-text` 嵌入(Ollama 在 AiKa-2)
