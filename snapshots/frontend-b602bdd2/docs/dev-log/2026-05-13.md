## 📌 規範 #16 新增 — 廣域 try/except 反模式

**起源故事**：

AiKa-1 (Windows) 從 5 月 11 日部署到今天 5 月 13 日，**從未發過任何心跳到 DO router**。dashboard 上 aika-1 一直顯示 `last_heartbeat="never"`，但**進程明明在跑**。

深挖代碼後找到根因：

```python
# agent.py 老版本:
def send_heartbeat():
    try:
        cpu = psutil.cpu_percent()
        memory = psutil.virtual_memory().percent
        disk = psutil.disk_usage('/').percent
        docker_ok = subprocess.run(["docker","ps"], ...).returncode == 0
        #            ↑↑↑ Windows 沒裝 Docker → FileNotFoundError
        ollama_ok = ...
        requests.post(ROUTER_URL+"/worker/heartbeat", json={...})
        #            ↑↑↑ 永遠到不了這行
    except Exception as e:
        logger.warning(f"HB failed: {e}")
        #            ↑↑↑ 默默把例外吞掉, 外界看不到問題
```

**「process 還在跑、CPU 占用看起來正常、但什麼都沒做」** —— 殭屍進程的標誌。

**規範 #16 全文**：

> 關鍵循環（心跳/輪詢）禁止用一個大 try/except 包整個函數。每個外部依賴（subprocess/網路請求）必須獨立 try/except 或預先 shutil.which() 檢查。
>
> 檢查清單：
> 1. subprocess 外部命令先 `shutil.which` 確認存在
> 2. requests 用 timeout + 明確 RequestException
> 3. except 必須 `logger.exception` 印 traceback 而非只 `.warning(str(e))`
> 4. review 看到「except Exception as e:」要質問能否讓它崩

## 🎓 今日重要教訓（給未來窗口）

1. **「殺進程」對 systemd 管理的服務無效**
   - 永遠先 `systemctl list-units | grep <name>` 看清全貌

2. **「症狀飄忽」是雙進程/HA 配置不對等的標誌**
   - 單次 curl 看不出，**連續 20 次測試**才能暴露 round-robin 行為

3. **HTTPS 頁面 fetch HTTP 後端會被瀏覽器 silent block**
   - Mixed Content Block 全部 26 個 API 請求失敗 = dashboard 「Mock」假象

4. **廣域 try/except 在關鍵循環是殭屍進程製造機**（規範 #16）
   - process 還在跑、CPU 占用正常、但什麼都沒做

5. **同類資料結構必須在所有來源保持一致**
   - dispatch 創的 task dict 有 `task_id`，PG rebuild 創的 dict 漏 `task_id`
   - → 前端 React `task.task_id` undefined → 表格空白

6. **byte 級 MD5 對 server-side config 太苛刻**（規範 #12 伸縮條款）
   - yml/conf/ini 被解析後丟註釋/空白，byte 不同但語義等價

7. **「收工郵件」必須真正寄出，不能只生 draft**（規範 #19）
   - Claude 必須驗證 SMTP 回應，不能聲稱「已寄出」但實際只是寫文件
